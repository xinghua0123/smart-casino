## 产品目标

经理提出运营目标，AI 基于实时状态生成受约束的方案，调用模拟器预演，经经理批准后生成现场任务；执行结果和后续变化持续回到看板。

主线：客流变化 → 预测容量不足 → 经理提出目标／约束 → 比较可行方案 → 人员执行 → 观察效果 → 条件变化时重新规划。

首版以本地模拟赌场演示。对外定位为 AI Floor Operations Copilot：理解经营目标、预演可行方案、持续检查计划是否有效。竞品独家性、真实增量收益和第三方系统兼容性均需要另外验证。

## 共同基础：可追踪的现场状态

1. 座位与队列：增加到达、排队、入座、离座、转桌和离开队列事件。一个玩家同时最多占一个座位，人数不能超过容量。
2. 桌台：区分关闭、准备开放、运行中、暂停；在现有布局中配置少量备用桌。动态最低投注额通过生效事件更新。
3. 人员：预置演示员工、技能、可用状态和分配关系；开桌必须满足人员与桌台条件。
4. 事件：记录事件 ID、实体 ID、发生时间、实体顺序／版本、场景 ID；处理重复与过期事件。
5. 新鲜度：独立心跳区分无人投注与数据中断。显示数据年龄，过期时暂停生成和批准可执行建议。
6. 指标：真实模拟座位状态替换访客数估算的占用率；新运营指标使用明确的统一时间口径，区分观测值、预测值和模拟假设。
7. 界面刷新：地图、行动中心和指标独立刷新，聊天期间继续更新；查询暂时失败不能显示成零客流。

## 功能 1：运营行动中心 + 持续评估计划的 AI

### 页面与任务

- 行动中心与地图联动：选择任务高亮桌台，选择桌台查看相关任务。
- 卡片包含问题、持续时间、数据依据、推荐动作、替代方案、预期效果、负责人、截止时间和状态。
- 首版动作：开放备用桌（包含荷官分配）、调整最低投注额。使用预置员工和角色记录操作者。
- 状态流程：待处理 → 已接单 → 执行中 → 观察效果 → 已关闭。支持拒绝、过期、取消及执行失败，并保留理由。
- 执行后展示 5／15 分钟排队、等待时间、在座人数、利用率、Theo 和额外人员成本。分别标记预测与观测，不将前后变化直接称为因果收益。

### 执行约束

- 相同问题更新已有任务，使用去重和冷却期避免任务泛滥或频繁调价。
- 每次执行前复查计划有效期、现场版本、桌台、最低投注额范围、人员和冲突任务。
- 接受建议生成带唯一命令 ID 的执行请求；现场模拟器确认后才标记生效。重试不重复执行。
- 明确最低投注额对后续入座／投注的生效时点；生成器、地图和模拟器使用同一有效配置。
- 人员不足或目标不可达时展示原因，不生成虚构的可行任务。
- 数据恢复或进程重启后，恢复任务与命令状态；不自动重放已经完成的动作。

### AI：事件驱动的重新规划

- 每份计划绑定数据快照、策略版本、关键假设和资源条件。
- 人员被占用、桌台停用、客流显著变化等关键事件触发有效性检查。
- 确定性校验先判断计划失效或需要复算，再调用 AI 解释和组织替代方案；不对每笔投注调用 LLM。
- 合并重复变化，只在计划失效、出现达到可配置改善阈值的替代方案或需要经理处理时通知。
- 展示哪个事件使哪条假设失效，以及新旧方案的区别。
- 已批准但尚未执行的计划失效时，阻止旧命令执行；涉及实质动作修改必须重新批准。
- 已生效动作不因重新规划被自动撤销；新的调整遵循普通审批与执行流程。

## 功能 2：未来地图／方案预演 + 目标驱动的 AI

### 地图与方案

- 时间切换：现在、15 分钟后、30 分钟后。
- 图层：占用率、排队压力、Theo；详情显示预测快照、数据时间、关键假设和适用条件。
- 对比保持现状、开放备用桌、调整最低投注额三类方案。
- 指标包括队列、等待时间、已服务人数、Theo、准备时间和额外人员成本；Theo 与成本分开呈现。
- 选定方案后进入功能 1 的任务流程。

### 预测与模拟

- 首版采用可解释的短期需求预测和情景模拟，使用近期到场率、离场率、在座时长及排队变化。
- 纳入座位容量、游戏偏好、最低投注额偏好、开闭桌状态、荷官技能及准备时间。
- 接入至少一个桌台之外的演示信号，例如团体餐饮结束；界面解释其对需求预测的影响。相关关系作为可配置演示假设，后续用真实数据校准。
- 不同方案使用相同起始状态、预测时点和外部客流假设；保存随机种子或等价可复现配置。
- 显式计算转桌、等待和离开，全场汇总不重复计算迁移客流。
- 低／中／高需求范围标为情景范围，不声称是经校准的统计置信区间。
- 预测模块只能读取已经发生的事件与已知业务日程；不能读取生成器尚未发生的随机结果或隐藏未来脚本。

### AI：自然语言目标转成可执行方案

示例指令：未来半小时，把主厅等待时间控制在五分钟内，不能增加人手，VIP 区最低投注额保持不变。

1. 解析目标区域、时间范围、目标指标、硬约束与偏好；将结构化理解展示给经理。
2. 首版支持有限且明确的约束集合：排除桌台、限定区域、人员增量上限、保留指定最低投注额，以及等待时间／成本／Theo 的优先级。
3. 查询统一现场快照，调用受控的预测、可行性校验和方案评估工具。
4. 返回可行方案、约束检查、预期指标、代价、数据时间和解释。
5. 支持连续修改，例如“不考虑 B08”，沿用已确认约束重新求解。
6. 无法满足目标时说明冲突约束，提出可选的放宽条件；未经经理选择不自行放宽。
7. 经批准的具体方案提交给行动中心，再由执行服务复查并执行。

LLM 负责意图理解、工具编排和解释；数值预测、容量计算、收益估算、约束校验及命令执行由业务模块负责。数字与解释关联同一快照，保留模型与工具版本。LLM 不直接修改数据库、执行任意 SQL 写入或绕过批准。LLM 暂时不可用时，保留手动约束表单和既有任务操作。

- 对保存的预测与对应实际时间段进行误差回看，至少覆盖等待时间或队列长度，并检查数据完整性。

## 演示与验收

### 场景 A：客流高峰与目标规划

触发客流高峰及一个跨业务信号。经理输入目标与约束，比较方案，再追加“不考虑 B08”。地图重新预演，经理选择方案，派单并确认生效；观测指标反映后续变化。

### 场景 B：资源变化与重新规划

方案待审核或已批准未执行时，触发荷官不可用。旧方案及时失效，AI 说明原因并提出仍然可行的替代方案；旧命令不能越过资源校验执行。

### 场景 C：数据中断与恢复

中断运营事件与心跳。界面显示过期，不将其解释为零需求；暂停新动作。恢复后复查任务，不重复执行历史命令。

### 核心检查

- 同一玩家最多占一个座位，在座人数不超过物理容量，转桌不会增加全场独立玩家数。
- 重复事件、重复点击、进程重启不产生重复任务或动作；冲突人员和桌台不可被同时占用。
- 接受、现场生效和效果观察是独立状态；拒绝或过期方案不能执行。
- AI 正确保留连续对话中的硬约束，不擅自改变最低投注额保护或人员上限。
- 方案违反约束、数据过期、资源版本改变时，确定性校验能够阻止执行。
- AI 解释中的关键数字与工具结果一致，显示数据时间；不可达目标不会被描述为已解决。
- 未来模拟使用共同输入进行比较，预测不能读取隐藏未来；执行动作影响后续现场事件。
- 以固定场景集验证目标解析、工具参数、约束满足、计划失效、LLM 故障回退；记录通过情况。
- 聊天期间地图与任务继续刷新；原有页面和查询功能通过回归检查。
- 完成前展示已实现范围、测试结果和已知限制，交用户验收；验收通过并提交最终版本后创建 `2.0`。
